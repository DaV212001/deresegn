4.2.4 Security Functionality Document  
 
AUTHENTICATION AND ACCESS CONTROL 
 
IDS Next Business Solutions is following standard authentication requirements such as (authentication type and number of 
factors) for all roles based on critical asset classification. The data associated with credentials is considered as critical asset.   
 
1. Access allocation based on the job role (RBAC). 
2. Type of access such as local, non-console, remote and level of privileges. IDS allows only user authentication; there 
Is no remote or VPN access. 
3. API authentication Is carried out using Tokenisation. 
4. Controls implemented to protect authentication credentials from being forged, spoofed, leaked, guessed, or 
circumvented.  
5. Role-Based Access Control (RBAC) is followed towards the application; all users are assigned roles as per RBAC. 
6. Credentials are protected using PBKDF2 hashing algorithm. 
     
FX1 Application does not provide any local, non-console (like Third Party VPNs, remote desktop) and other levels of privileges. 
FX1 application Implemented token-based authentication for API's for accessing any critical assets. All the credentials used 
for accessing application are securely hashed using PBDKF2 algorithm. 
 
FX1 Application supports MFA using OTP (email) based login and IP Based login as well per user and same can be enabled

Secure authentication must be enforced to all accounts generated or managed by the application by the completion of 
installation and for subsequent changes after installation.

Do not use (or require the use of) default administrative accounts for other necessary software (EG.: the payment 
application must not use the database default administrative account).

Enforce the changing of all default application passwords for all accounts that are generated or managed by the

• 
Assigns unique IDs for user accounts.

o 
Something you know, such as a password or passphrase.

Something you have, such as a token device or smart card.

o 
Require a minimum length of at least seven (12) characters.

Alternatively, the passwords/phrase must have complexity and strength at least equivalent to the parameters

ENCRYPTION & SECURE COMMUNICATION 
 
FX1 Application renders password unreadable all times in the rest and transit. Application uses one-way strong cryptographic 
PBKDF2 hashing algorithm and each password is concatenated with unique random salt value and hashed and stored. Salt 
Value is encrypted and stored along with password hashes in same table in the database.  
 
Application is hosted over TLS 1.2 protocol and should be accessed only through Https protocol. If the application is hosted 
over the public network, CA authorized security certificate to be installed or if it’s hosted in the intranet Self-signed security 
Certificate with RSA 4096-bits to be installed. Https communication ensures that all the data sent over it are encrypted in 
transit and it’s not prone to man-in-the-middle attack.

Web Software Attack Mitigation 
 
Mitigating attacks on web applications is crucial for maintaining the integrity and security of the FX1. This section addresses the various 
security controls implemented to protect the application from common web-based threats. It includes details on defense mechanisms, 
security headers, input validation, resource protection, and strategies for handling malicious content and attacks targeting web interfaces. 
 
Software Security Controls for Common Web Attacks 
 
FX1 protects against: 
• 
SQL Injection 
• 
XSS (Cross-Site Scripting) 
• 
CSRF (Cross-Site Request Forgery) 
• 
Broken Authentication 
• 
Parameter Tampering 
• 
Directory Traversal 
• 
SSRF & Request Manipulation 
•

IDS Risk Management Framework 
 
The first steps in information security strategic planning in any form of business are risk management and risk evaluation. This 
is necessarily broad, including business processes, people and physical infrastructure, as well as the information system. 
 
The security risk evaluation needs to assess the asset value to predict the impact and consequence of any damage. 
 
The main objective of this framework is to have IDS aligns to applicable models for organizations to measure, manage and 
follow upon assets, risk and controls implementation in the organization.

Risk assessment and management 
 
The risk assessment comprises the qualitative assessment and quantitative measurement of individual risk, including the 
interrelationship of their effects. Risk management constitutes a strategy to avoid losses and use available opportunities or, 
rather, opportunities potentially arising from risk areas.  
 
Normally, no single strategy will be able to cover all IT asset risk, but a balanced set of strategies will usually provide the best 
solutions. Once the risk is identified, it can be evaluated as acceptable or not. If it is acceptable, no further actions are required 
other than communicating and monitoring the risk, but if the risk is not acceptable, it must be controlled through four separate 
options of prevention and/or mitigation measures: 
 
1. Reduce the impact. 
2. Reduce the likelihood. 
3. Transfer the risk (to insurance or a subcontractor). 
4. Avoid the risk. (Temporarily distancing the target from the threat summarizes the potential impact definitions for the

Threat assessment and rating methodology 
 
Each threat is derived from a specific vulnerability, rather than identifying threats generally without considering vulnerability.

assessment accounts for the entire code base, including how the use of third-party, open-source, or shared components or 
libraries, APIs, services, and applications used for the delivery and operation of the software may be leveraged in an attack. 
The assessment results in a recorded inventory of threats and design flaws.
